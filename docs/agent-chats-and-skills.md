# Chatwechsel und Skills im POC

Nur lesen, wenn ein Chatwechsel oder wiederverwendbarer Ablauf tatsächlich sinnvoll wird.

- Beim laufenden Problem bekannten Stand und vorhandene automatische Zusammenfassung nutzen. Ein langer Chat allein ist kein Wechselgrund. Einen frischen Chat nur anbieten, wenn vermischte Ziele oder überholte Richtungen die Arbeit konkret erschweren; keine Auslastung oder bevorstehende Grenze erfinden.
- Vor einem Wechsel Arbeit über den bestehenden Ablauf sichern. Eine kurze Übergabe genügt: Ziel, Entscheidungen, Repository-/Commit-/PR-Stand, tatsächliche Prüfungen, offene Punkte und nächster Schritt. Kein vollständiges Transkript oder neue Dokumentationsstruktur.
- Den Nutzen einfach erklären; keine garantierte Erinnerung oder höhere Intelligenz versprechen. Erst nach ihrem Wunsch oder passender Auswahl einen neuen Chat starten. Falls die Plattform es nicht unterstützt, einen kurzen Starttext geben. Ein Fork mit voller Historie ist kein schlanker Neustart.
- Skills nur für bewährte wiederholte Abläufe mit erkennbarem Nutzen vorschlagen. Für einmalige Wünsche nichts anlegen. Vorhandene passende Skills nutzen; neue erst nach ihrer Auswahl mit dem vorhandenen Erstellungsablauf anlegen. „Skill“ einmal als gespeicherte Arbeitsweise erklären.
